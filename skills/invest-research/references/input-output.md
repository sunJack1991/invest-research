# 输入与输出约定

用户使用自然语言即可，Agent可用[请求模板](../assets/request.json)记入请求，用[结论摘要](../assets/summary.md)展示结果。此页定义本包交互规则，不要求任何特定厂商API。

## 1. 开始任务所需信息

不同任务只追问会阻碍当前工作的必要信息；已给的信息不重复询问。能从上下文明确识别的任务类型可由Agent归类并在结果中说明，不能擅自改成另一项任务。

| 任务 | 必要输入 | 缺失时如何处理 |
|---|---|---|
| 研究公司、股票或ETF | 可唯一定位的标的：名称或代码；有歧义时补市场、份额或证券类别 | 先确认标的，不把同名公司、不同上市证券或ETF份额混用 |
| 复核已有报告 | 待复核报告的正文或可读取文件；可明确识别其标的与时点 | 读取报告确认范围；拿不到正文时说明未读取，不编造复核结果 |
| 解释或比较方法 | 具体问题或比较对象，例如RI与DCF的适用条件 | 无需资产、持仓或完整IPS；问题不清时只追问问题范围 |

请求记录的 `task_type` 分别为 `research`、`review`、`explain`。通用研究是默认范围 `general_research`。不要求用户提供原书、全部阅读笔记、个人资产表、税务信息或交易授权才开始通用研究。

用户提供的信息不等于已核实的事实。标的身份、报价、财报、政策确认和来源实际可读性仍须据实核对；未经确认的内容保留未知。

## 2. 个人决策评估的条件必填信息

用户明确要求适配自身、检查个人仓位或评估拟议动作时，记录 `scope=personal_decision`。至少核对下列信息；可用脱敏数据，不能索取登录凭据或与判断无关的身份信息。

| 信息 | 最低需要明确的内容 | 未提供或未核实的限制 |
|---|---|---|
| 决策目的与动作 | 用途、期限、货币；是新买、加仓、持有、减仓还是退出的研究评估 | 不能把一般“看好”转换为个人动作建议 |
| 用户自己的IPS | 当前版本、确认状态、适用范围和相关P01–P10参数；政策不适用项须有理由 | 不套用维护者的配置或阈值；G1保持待查 |
| 资金与用途约束 | 可投资组合分母、实际可用资金、应急及近期支出、负债和收入中断承受能力 | 不推算可买金额，不认定持有能力已满足 |
| 持仓及相关敞口 | 当前持仓、市值时点、直接和穿透敞口、拟议动作的前后影响 | 不判断新增仓位或集中度符合政策 |
| 税务、账户与工具约束 | 与该工具和动作有关的适用身份、账户权限、成本税负与结算限制 | 不确认实施可行性；关键未知单独阻断相应结论 |

这些信息缺失不阻断能够独立完成的公司或ETF研究；输出必须说明“通用研究可进行，个人适配尚不能完成”，列出本次真正需要补充的最小信息。个人资料齐备也不自动代表已核实或五门通过。

当前项目只研究与记录，不连接账户或执行交易。研究结论、用户确认IPS和实际交易授权分别处理，不要求交易授权才能做研究，也不因研究完成推定授权。

## 3. 可选输入与默认行为

| 可选信息 | 未提供时的默认处理 |
|---|---|
| 重点问题、行业或业务分支、研究假设 | 按框架开展适用分支；假设与事实分开，不臆造用户立场 |
| 研究深度：auto、light、full | 默认auto；先核所需层级，按用户政策及问题复杂性展开。light仍保留五门、反向数值和必要核查 |
| 截止日期 `as_of` | 以运行日期为请求截止日，结果写明实际取得的财报期间、披露日和报价时间，不暗示已取得实时数据 |
| 用户提供的披露、报价或其他资料 | 若环境允许且任务需要，取得可核来源；不可得时列数据缺口。不能把书内历史数字当作当前事实 |
| 比较标的、同口径基准、预期持有期限 | 仅在资料与适用条件明确后比较，不默认用户期限、回报率或数值目标 |
| 输出语言 | 默认简体中文 |
| 可选报告类型 | 默认空列表，只展示必要结论；不自动生成整套长报告 |
| 格式、写入文件与输出目录 | 默认Markdown在对话中展示，不写文件；要求落盘时需用户工作区位置，禁止写回基础资源 |

历史截止日研究按当时可获得的信息完成，不能使用之后披露的事实形成事前结论；事后对照如被请求须另标。用户提供旧报价时，注明其时点和用途，不混充截止日现价。

默认项可直接执行并在有意义时说明；不会替代必须确认的标的身份、政策参数或个人事实。只在用户要求文件或特定格式时生成对应产物；格式工具不可用要明确说明，不把Markdown文件改后缀冒充PDF。

## 4. 必须展示的结论

默认按下列顺序显示简明摘要；不默认展示全部A–M字段、运行JSON或长篇阅读记录。实质研究与底稿义务按适用分支保留，不能因只要摘要就跳过核查。

| 必须展示 | 内容与边界 |
|---|---|
| 对象、时点与完成范围 | 哪只证券或哪个问题；请求截止日与实际数据时点；通用研究或个人评估；已完成及未完成部分 |
| 核心结论及理由 | 研究候选、观察、排除或信息不足，并给决定性理由；不强制给买卖答案，不把研究候选等同买入许可 |
| 决定性证据 | 最关键的支持依据和反证；区分书籍原则、个人政策、公司事实、推算与情景；实际使用的来源可定位 |
| 价格、估值与条件 | 有可靠输入时列价格日期/币种、合理价值或情景范围及关键假设；无法可靠估值时明确显示原因和缺失输入，不强填目标价 |
| 五门G1–G5 | 分别为通过、待查或否决，简述原因；任一待查或否决不新增，不得用总分抵消。通用研究缺个人政策时G1待查 |
| 主要风险与最强反方 | 可能造成永久损失或推翻论点的机制、证伪信号；不只列笼统“市场风险” |
| 关键未知与下一步 | 哪些缺口会改变结论、需要补什么资料或触发何种复核；允许明确“不行动” |
| 适用边界与来源 | 是否完成个人适配、未核事实与数据限制；方法和政策版本简注，来源保留必要定位；研究不等于交易授权 |

复核任务另外必须显示“原结论是否仍有支持、重大错误或遗漏、受影响的判断与需要修订处”；保留原报告，修订作为新版本。方法解释任务以“答案、适用条件、推算示例和限制”为核心；五门、市场报价和个人仓位等不适用项写明理由，不机械索要无关数据或捏造估值。

只有个人政策与相关事实已核、适用研究完成、五门状态支持时，才可以说明拟议动作是否符合本次已核政策；依然不生成交易授权。仓位或价格范围必须能追溯至用户政策、数据及计算，不能填入模板默认数值。

## 5. 可选报告

摘要始终展示。用户可指定一项或多项；报告详略、研究深度、文件格式分别选择，互不替代。

| 报告类型 | 请求标识 | 主要内容 |
|---|---|---|
| 完整研究报告 | full_research | 商业、管理、财报生存、估值、反方、五门与复核；依适用范围展开 |
| 估值与敏感性附录 | valuation_appendix | 输入和口径、正向与反向估值、情景、敏感性、股权桥接及复算；无数据则报告缺口 |
| 证据与待核附录 | evidence_appendix | 来源定位与时点、证据类型、同源去重、事实/推算/情景、未知与核验路径 |
| 完整决策记录 | decision_record | 复用原决策模板及A–M适用分支；个人政策、拟议动作和未知明确分开，授权栏不预填通过 |
| 报告复核与修订清单 | review_report | 重大问题、受影响结论、证据差异及修订建议；可读原文是前提 |

文件只落在用户指定工作区；研究产出不是主体方法、原书或原阅读状态的权威源。主体无需引用任何特定独立报告，也不把既有个案作为运行前提。

## 6. 典型请求及预期行为

- “研究某只ETF。”：能唯一定位即可开始通用研究；无法确认份额时只补问身份。提供摘要，不要求先报个人资产。
- “这只股票适合我加仓吗？”：查用户政策、用途、持仓与可用资金等相关事实；不足时先做可完成的研究，G1待查，不输出确定加仓额度。
- “复核这份报告，只给关键问题。”：必须实际读到报告；展示原结论支持程度、重大问题及下一步，不默认生成文件。
- “解释RI与DCF差别。”：无需账户、IPS或现价；用明确标为推算的教学例解释适用条件。
- “按指定历史日期研究，并给完整报告及估值附录。”：固定信息截止日，展示摘要与被请求的附加报告；无输出目录时可在对话展示，不自行写入基础目录。

验收须检查：缺标的或报告不捏造结果，缺IPS不阻断通用研究且不放行个人新增，未知不填零，摘要字段不因未选长报告而消失，可选报告不默认为全选，历史截止日不混入未来事实。记录用户请求与最终实际交付，不能只记录“用户要了什么”。
